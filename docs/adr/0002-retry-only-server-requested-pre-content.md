# ADR 0002 — 再試行はサーバー指示と未出力の失敗に限定する

状態: 採用

## 背景

プロバイダのストリームをラップすると、再試行の条件と待ち時間はこの拡張が決めます。
広く再試行すると恒久的な上限で無駄に待ち、狭すぎると今回の 55 秒の窓を直せません。

## 決定

次の2つを同時に満たす失敗だけを再試行します。

1. エラー本文に `"retryDelay": "Ns"`（`google.rpc.RetryInfo`）または `Please retry in Ns` がある。
2. 失敗した試行がまだ内容を出力していない。

待ち時間はサーバー指定 + 1 秒のマージン、上限 120 秒とし、初回 + 3 回で打ち切ります。

## 理由

- 再試行指示はサーバーが「一時的で、この時刻に回復する」と表明した情報です。
  これを条件にすれば、恒久的なクォータ枯渇や認証エラーで無駄に待ちません。
- 出力開始前の失敗だけなら、破棄した試行を再送しても二重出力になりません。
- マージンは時計のずれを吸収し、上限は壊れた値でセッションが長時間止まるのを防ぎます。
- 無料枠の毎分上限は1窓で回復するため、2回目の試行で通常は成功します。

## 却下した代替

- 429 や `quota exceeded` という文言だけで再試行する案。
  再試行指示の無い恒久的な上限でも待ち続け、実行時間を無駄にします。
- 固定バックオフや指数バックオフを使う案。
  サーバーの窓（55 秒など）より短いと無駄な再試行になり、長いと必要以上に遅れます。
- 出力開始後も失敗を破棄して再試行する案。
  すでに受信した内容を再送すると同じ出力が二重に現れるか、途中の内容が失われます。
- 待ち時間や試行回数を設定できるようにする案。
  設定なしで安全な既定値を持たせ、必要になった時点で追加します。
