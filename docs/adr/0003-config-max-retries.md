# ADR 0003: 試行回数だけを設定ファイルで受け、全体とプロジェクトの順でマージする

- 状態: 採用
- 日付: 2026-10-01
- 対象: 設定の読み込みと `maxRetries` の決定

## 背景

ADR 0002 は待ち時間と試行回数を固定し、設定は「必要になった時点で追加」としていました。
無料枠の大きさやプロジェクトの使い方は環境ごとに違うため、試行回数だけは調整したいという需要がありました。

## 決定

- 設定ファイルは `~/.pi/agent/retry.json`（または `$PI_CODING_AGENT_DIR/retry.json`）と、
  信頼済みプロジェクトの `<cwd>/.pi/retry.json` の2箇所です。
- プロジェクトの値が全体の値を上書きします。未信頼のプロジェクトのファイルは読みません。
- 設定できるキーは `maxRetries`（0〜10の整数、既定3）だけです。
- 不正な値・壊れた JSON・オブジェクト以外の JSON は、警告を出して既定値で動作します。
- 読み込みは `session_start` ごとに行い、次のリクエストから反映します。

## 理由

- 試行回数は環境依存です。プロジェクト単位で変えられる方が、全体の既定を壊さずに済みます。
- 設定が壊れてもセッションを止めないため、読み込みと検証は session_start で完結させ、警告は UI に出します。
- 待ち時間を設定できるようにすると、サーバーが指定した窓より短い値や長い値を作れてしまい、
  ADR 0002 の判断（サーバー指示に従う）と矛盾します。

## 却下した代替

- 環境変数での指定。プロジェクト単位の切り替えができず、設定の存在に気付きにくい。
- 全体設定ファイルのみ。プロジェクトごとの上限の違いを表現できない。
- Pi の `settings.json` への相乗り。Pi 内部の構造に依存するため、公開 API だけで完結しません。
- `marginMs` や `maxDelayMs` も設定可能にする案。サーバー指示より短いと無駄な再試行になり、
  長いと必要以上に待ちます。固定値で足ります。
