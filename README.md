# pi-retry

Google プロバイダのレート制限（429）を、サーバーが指定した待ち時間で自動再試行する Pi 拡張です。

Pi 本体は `quota exceeded` や `billing` を含むエラーを恒久的なクォータ枯渇とみなして即停止します。
Google の無料枠の「毎分あたりの入力トークン」のような一時的な上限では、
応答本文の `google.rpc.RetryInfo` が再試行までの待ち時間を返しますが、
この分類では再試行されず、実行が終わってしまいます。

この拡張は `google` プロバイダのストリームを置き換え、
サーバー指定時間に1秒を加えた時間（1回あたり上限120秒）待って同じリクエストを再送します（再試行は最大3回）。

```
リクエスト → 429（本文: "retryDelay": "55s"）
  ├─ まだ何も出力していない → 56秒待って再送（再試行は最大3回）
  └─ すでに出力を開始している → 再試行しない（そのままエラーを報告）
```

## 動作

再試行するのは、**次の2つを同時に満たす失敗**だけです。

1. サーバーが再試行を指示している（エラー本文に `"retryDelay": "Ns"` か `Please retry in Ns` がある）
2. 失敗した試行がまだ何も出力していない

既定の動作:

| 項目 | 値 |
|---|---|
| プロバイダ | `google` |
| API | `google-generative-ai` |
| 適用範囲 | 通常のターン、コンパクション、要約（すべて同じストリーム経由） |
| 待ち時間 | サーバー指定 + 1秒（1回あたり上限120秒） |
| 試行回数 | 初回 + 3回 |
| 中断 | 待機中に Esc すると `aborted` として終了し、再試行しない |

再試行の対象外:

- 再試行指示の無いエラー（恒久的なクォータ枯渇、認証エラーなど）は、これまで通り即時に報告します。
- 出力を開始した後の失敗は再試行しません。
  すでに流した内容を破棄して再送すると、同じ出力が二重に現れるためです。

設定項目はありません（上限は実装内の固定値です）。

## インストール

```bash
pi install git:github.com/kurowashi/pi-retry
```

ref を固定する場合は `pi install git:github.com/kurowashi/pi-retry@<tag|commit>`。

ローカルの作業コピーを使う場合:

```bash
pi install /path/to/pi-retry
```

または直接読み込み:

```bash
pi --extension /path/to/pi-retry/src/index.ts
```

インストール後、`google` プロバイダのモデル（例: `google/gemma-4-31b-it`）でそのまま有効になります。
動作確認は Pi 0.87.1 で行っています。

## なぜ Pi 標準の再試行設定では足りないか

Pi のプロバイダ再試行は `Retry-After` ヘッダを前提にしています。
Google は 429 にこのヘッダを付けず、待ち時間は応答本文の `RetryInfo` にだけ入っています。
ヘッダが無いときのバックオフは 0.5 秒から最大 8 秒で、55 秒の窓は待ち切れません。

## 制約

- 対象は `google` プロバイダだけです。`google-vertex` は必要になった時点で追加します。
- 再試行しても解決しない上限（日次クォータなど）では、上限回数で停止します。
