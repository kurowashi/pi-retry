# pi-retry

Google プロバイダのレート制限（429）を、**サーバーが指定した待ち時間で**自動再試行する Pi 拡張です。

Pi 本体は `quota exceeded` や `billing` を含むエラーを恒久的なクォータ枯渇とみなして即停止します。
Google の無料枠には「毎分あたりの入力トークン」のような一時的な上限があり、
応答本文の `google.rpc.RetryInfo` に再試行可能時刻が入っていますが、
この分類では再試行されず、実行が終わってしまいます。

この拡張は `google` プロバイダのストリームを置き換え、サーバーが指示した時間だけ待って同じリクエストを再送します。

```
リクエスト → 429 (本文: "retryDelay": "55s")
  ├─ まだ何も出力していない → 56秒待って再送(最大3回)
  └─ すでに出力を開始している → 再試行しない(そのままエラーを報告)
```

## 動作

再試行するのは、**次の2つを同時に満たす失敗**だけです。

1. サーバーが再試行を指示している（エラー本文に `"retryDelay": "55s"` か `Please retry in 55.0s` がある）
2. 失敗した試行がまだ何も出力していない

| 項目 | 値 |
|---|---|
| 待ち時間 | サーバー指定 + 1秒（上限 120秒） |
| 試行回数 | 初回 + 3回 |
| 対象プロバイダ | `google`（`google-generative-ai`） |
| 中断 | 待機中に Esc すると `aborted` として終了 |

再試行の対象外:

- 再試行指示の無いエラー（恒久的なクォータ枯渇、認証エラーなど）は、これまで通り即時に報告します。
- 出力を開始した後の失敗は再試行しません。
  すでに流した内容を破棄して再送すると、同じ出力が二重に現れるためです。
- 設定はありません。上限は `src/retry.ts` の `DEFAULT_RETRY_POLICY` に固定です。

## インストール

```bash
pi install git:github.com/kurowashi/pi-retry
```

ref を固定する場合は `pi install git:github.com/kurowashi/pi-retry@<tag|commit>`。

ローカルの作業コピーを使う場合:

```bash
pi install /path/to/pi-retry
```

または直接読み込み:

```bash
pi --extension /path/to/pi-retry/src/index.ts
```

インストール後、`google` プロバイダのモデル（例: `google/gemma-4-31b-it`）でそのまま有効になります。

## なぜ設定 `retry.provider.maxRetries` では足りないか

Pi にはプロバイダ再試行の設定がありますが、このエラーには効きません。

- Google は 429 に `Retry-After` ヘッダを付けず、待ち時間は応答本文の `RetryInfo` にだけ入っています。
- Pi のプロバイダ再試行は、ヘッダが無いとき 0.5秒から最大8秒のバックオフにしかなりません。
  55秒の窓は待ち切れません。
- 再試行を使い切った後のエラーはエージェント層の分類に戻り、`quota exceeded` を含むため再試行されません。

## 制約

- 対象は `google` プロバイダだけです。`google-vertex` は必要になった時点で追加します。
- コンパクションや要約も同じストリーム経由なので、同じ待ち・再試行の対象になります。
- 再試行しても解決しない上限（日次クォータなど）では、上限回数で停止します。
